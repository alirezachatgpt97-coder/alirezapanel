# هدف 1 vCPU / 1 GiB RAM

مصرف واقعی پایه و مصرف زیر بار **در این محیط اندازه‌گیری نشده‌اند**. `/proc` کامل، systemd واقعی و VPS یک‌گیگابایتی در دسترس نبود. عدد ساختگی برای حافظه یا ظرفیت کاربر ارائه نمی‌شود.

## کارهای انجام‌شده

- مسیر نصب همچنان باینری‌های pinned را دانلود و به‌صورت ترتیبی بررسی/باز می‌کند؛ Docker، npm، Node.js و کامپایلر روی مقصد نصب نمی‌شوند.
- داده‌های بزرگ upload/download/relay به‌صورت stream منتقل می‌شوند. پاسخ‌های تبدیل‌شده سقف اندازه دارند؛ subscriptionها و اتصال‌های نود از محدودیت‌های هم‌زمانی موجود استفاده می‌کنند.
- WebSocket بومی حفظ شده است. حلقهٔ جایگزین داشبورد از ۲ به ۵ ثانیه تغییر کرده، تنها یک نمونه دارد، در صفحهٔ پنهان درخواست نمی‌فرستد و درخواست کند هم‌پوشان ایجاد نمی‌کند. حلقه‌های بومی سایر صفحات و قابلیت‌های زنده حذف نشده‌اند.
- فیلتر محتوا و لاگ کاربر on-demand هستند؛ بخش فیلتر یک حلقهٔ وضعیت تازه ایجاد نمی‌کند. نمایش کاربر برای هر بار حداکثر ۱۰۰ کارت می‌سازد؛ جست‌وجو دسترسی به سایر کاربران را حفظ می‌کند.
- فایل‌های JS/CSS دارای `v=2.8.0` برای یک روز immutable cache دارند؛ URL بدون این نسخه باید revalidate شود. هیچ فونت دوردست، تصویر بزرگ یا daemon تازه اضافه نشده است. جلوه‌های بومی ورود و جزئیات رابط حفظ شده‌اند.
- Observer برند فقط در تغییرات مرتبط با ناوبری/تصویر، بازبینی هویت را دوباره زمان‌بندی می‌کند؛ هر تغییر آمار باعث آن کار نمی‌شود.
- نصب تازه پایگاه داده، WAL و HTTP session مربوط به بخش بازنشستهٔ DNS client را نمی‌سازد. ارتقای دارای دادهٔ قدیمی همان لینک‌ها و وضعیت را حفظ می‌کند.
- هدف‌های نرم Go از نصب‌کنندهٔ موجود حفظ شده‌اند: VPN حدود ۳۰٪ RAM، حداکثر ۳۰۰ MiB؛ DNS حدود ۱۲٪ RAM، حداکثر ۱۶۰ MiB. `GOMEMLIMIT` محدودیت کل RSS یا ضمانت جلوگیری از OOM نیست؛ هسته‌ها و حافظهٔ خارج از heap نیز مصرف دارند.
- لاگ اتصال به‌صورت موجود هر پنج دقیقه توسط logrotate بررسی می‌شود، آستانهٔ 4 MiB و یک نسخهٔ قبلی دارد. این آستانه سقف سخت نیست: زیر ترافیک زیاد فایل تا نوبت بعدی می‌تواند بزرگ‌تر شود. `copytruncate` ممکن است در فاصلهٔ کوتاه کپی/قطع، برخی رویدادها را از دست بدهد. لاگ‌های AdGuard و retention آن تغییر نکرده‌اند.
- محدودیت نرخ journal سرویس‌ها حفظ شده است؛ تنظیمات سراسری journald سیستم دستکاری نشده‌اند.

## اندازه‌گیری روی سرور آزمایشی خودتان

ابتدا نصب پایه، بدون کاربران فعال و Coreهای اختیاری را اندازه بگیرید:

```bash
sudo alirezapanel resources
sudo systemctl show alirezapanel alirezapanel-vpn alirezapanel-dns -p MemoryCurrent -p CPUUsageNSec -p TasksCurrent
ps -eo pid,ppid,comm,rss,%cpu --sort=-rss
free -m
sudo du -sh /opt/alirezapanel /var/lib/alirezapanel-nodes /var/log/vpn-ui /var/log/journal /var/backups/alirezapanel
```

بعد همان مجموعه را پس از فعال‌کردن **پروتکل‌های واقعاً مورد استفاده** و تحت بار کنترل‌شدهٔ کاربران اندازه بگیرید. تعداد اتصال‌ها، نرخ DNS، اندازهٔ لیست‌های فیلتر، پروتکل‌ها، Coreها، RSS، CPU، swap، تأخیر و خطاها را ثبت کنید. مصرف مرورگر را از مصرف سرور جدا بدانید. داشتن چند Core، WireGuard/Kernel VPN، لیست بزرگ DNS یا بار زیاد می‌تواند منابع بیشتری لازم داشته باشد.

هنگام upgrade فضای آزاد باید برای stage دانلودها و یک کپی کامل از VPN، AdGuard و state کافی باشد. Backup و دادهٔ DNS ممکن است از باینری‌ها بزرگ‌تر باشند. Installer قبل از mutation پشتیبان می‌گیرد؛ فضای ۲ GiB یک ظرفیت عمومی برای هر اندازهٔ داده نیست.

برای قبول این هدف روی ۱ GiB، نصب تازه و upgrade را روی VPS آزمایشی با همین محدودیت اجرا کنید، وضعیت OOM و swap را هنگام دانلود، راه‌اندازی، اعمال فیلتر و بار واقعی بررسی کنید. چنین آزمونی در این تحویل انجام نشده است.
