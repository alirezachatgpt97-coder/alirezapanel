alirezapanel رابط کامل vpn-ui و AdGuard Home را با ورود و ناوبری یکپارچه ارائه می‌کند. مدیریت نود، کلاینت‌های اختصاصی DoH، فیلتر محتوای هر کاربر، صفحهٔ ساب با نمودار مصرف واقعی و نمایش لاگ اتصال کاربران به این مجموعه اضافه شده‌اند. نام پنل و ساختار اصلی رابط حفظ شده‌اند.

تمام کد یکپارچه‌سازی در `install.sh` قرار دارد؛ فایل‌های اجرایی موردنیاز هنگام نصب از منابع اصلی دانلود و با SHA-256 بررسی می‌شوند. بنابراین نصب **آنلاین** است.

<a id="install"></a>
## نصب سریع با یک دستور

با SSH به سرور وصل شوید. روی **Debian 12/13 یا Ubuntu 24.04، معماری amd64 و با کاربر root** اجرا کنید:

```bash
curl -fL --retry 3 --connect-timeout 15 --max-time 180 https://raw.githubusercontent.com/alirezachatgpt97-coder/alirezapanel/main/install.sh -o install.sh && bash install.sh
```

با کاربر دارای دسترسی `sudo`:

```bash
curl -fL --retry 3 --connect-timeout 15 --max-time 180 https://raw.githubusercontent.com/alirezachatgpt97-coder/alirezapanel/main/install.sh -o install.sh && sudo bash install.sh
```

این دستور `install.sh` را در پوشهٔ فعلی ذخیره می‌کند و فقط پس از دانلود موفق آن را اجرا می‌کند. سپس منوی انتخاب دامنه/IP و SSL باز می‌شود. اگر فایلی با همین نام دارید، نسخهٔ دانلودشده جایگزین آن می‌شود.

اگر `curl` نصب نیست، ابتدا با root اجرا کنید:

```bash
apt-get update && apt-get install -y ca-certificates curl
```

> نصاب را به روش `curl ... | bash` یا `bash <(curl ...)` اجرا نکنید. این نصاب برای استخراج کدهای داخل خودش، از مسیر فایل اجرایی دوباره می‌خواند و به یک فایل واقعی نیاز دارد. دستور تک‌خطی بالا این نیاز را رعایت می‌کند و ورودی ترمینال را برای منوی نصب آزاد نگه می‌دارد.

### مراحل نصب و اولین ورود

1. دستور نصب را اجرا کنید.
2. یکی از حالت‌های **دامنه با SSL معتبر**، **IP عمومی با SSL معتبر**، **HTTPS خودامضا** یا **HTTP** را انتخاب کنید.
3. دامنه یا IP خواسته‌شده را بدون `https://`، پورت یا مسیر وارد کنید.
4. پس از پایان نصب، آدرس کامل پنل را از خروجی کپی کنید؛ مسیر خصوصی انتهای آدرس را هم نگه دارید.
5. وارد پنل شوید و اینباند، پروتکل و کلاینت موردنیاز را بسازید. هسته‌های اختیاری صرفاً با نصب پنل همگی فعال نمی‌شوند.

برای مشاهدهٔ آدرس پنل و اطلاعات ورود اولیه:

```bash
sudo alirezapanel info
sudo alirezapanel credentials
```

`credentials` فقط نام کاربری و **رمز اولیه** را نشان می‌دهد؛ رمزهایی که بعداً در پنل تغییر می‌دهید در این خروجی به‌روز نمی‌شوند.

برای بررسی فایل پیش از نصب نیز می‌توانید بعد از دانلود اجرا کنید:

```bash
bash install.sh --self-test
```

<a id="ssl"></a>
## دامنه، IP و SSL

پورت پیش‌فرض HTTPS پنل **8443** است تا پورت 443 برای اینباندها آزاد بماند. آدرس دقیق و مسیر ورود بعد از نصب چاپ می‌شود.

| حالت | نتیجه | پیش‌نیاز اصلی |
| --- | --- | --- |
| `domain` | گواهی معتبر برای دامنه | رکوردهای A/AAAA صحیح و دسترسی عمومی TCP 80 |
| `ip-acme` | گواهی معتبر کوتاه‌عمر برای IP عمومی | IP عمومی قابل تأیید و دسترسی TCP 80 |
| `ip` | HTTPS خودامضا، مگر گواهی خارجی بدهید | هشدار اعتماد مرورگر برای گواهی خودامضا طبیعی است |
| `none` | HTTP، پیش‌فرض پورت 8080 | ارتباط رمزگذاری نمی‌شود |

### نصب با دامنه

بعد از دانلود `install.sh`، دامنهٔ خود را جایگزین کنید:

```bash
sudo env ALIREZA_TLS_MODE=domain ALIREZA_HOST=panel.example.com bash install.sh
```

رکوردهای دامنه باید به همین سرور برسند. اگر رکورد AAAA دارید، مسیر IPv6 هم باید درست باشد. پورت TCP 80 باید هنگام صدور **و تمدید** قابل دسترسی باشد. نصاب برای آزادکردن پورت، وب‌سرور دیگری را خودکار متوقف نمی‌کند.

### نصب با SSL معتبر روی IP عمومی

در این دستور حتماً IP عمومی واقعی سرور خود را جایگزین کنید:

```bash
sudo env ALIREZA_TLS_MODE=ip-acme ALIREZA_HOST=YOUR_PUBLIC_IP bash install.sh
```

`ip-acme` به `ALIREZA_HOST` نیاز دارد؛ IP خصوصی، IP پشت NAT بدون دسترسی ورودی، یا صرفاً انتخاب این حالت بدون مشخص‌کردن IP کافی نیست. منوی تعاملی نصب، IP را از شما می‌پرسد.

### تمدید و استفاده در کانفیگ‌ها

```bash
sudo alirezapanel ssl
sudo alirezapanel ssl status
sudo alirezapanel ssl renew
sudo systemctl status alirezapanel-cert-renew.timer --no-pager
```

- برای گواهی‌هایی که نصاب دریافت کرده، بررسی تمدید هر شش ساعت با کمی تأخیر تصادفی انجام می‌شود.
- مسیرهای پایدار گواهی و کلید: `/etc/alirezapanel/tls/cert.pem` و `/etc/alirezapanel/tls/key.pem`.
- در اینباند TLS جدید، گواهی معتبر پنل برای فیلدهای خالی پیشنهاد/جای‌گذاری می‌شود. نام میزبان و SNI باید با گواهی سازگار باشند.
- اینباندهای قبلی، گواهی سفارشی و تنظیمات Reality خودکار به TLS تبدیل نمی‌شوند.
- DoH مدیریت‌شده از HTTPS و گواهی همان درگاه پنل استفاده می‌کند.
- گواهی‌های خارجی خودکار وارد تمدید ACME نمی‌شوند؛ تمدیدشان با صادرکننده/ابزار خود شماست.
- تعویض گواهی درگاه با بارگذاری مجدد انجام می‌شود؛ اگر هستهٔ VPN مصرف‌کنندهٔ همان گواهی باشد، راه‌اندازی مجدد لازم ممکن است اتصال‌ها را کوتاه قطع کند.

<a id="clients"></a>
## کلاینت‌ها، فیلتر محتوا و Gaming Mode

کلاینت را با فرم اصلی پنل بسازید. از دکمهٔ **«فیلتر / گیمینگ»** گزینه‌ها را انتخاب و کلاینت را ذخیره کنید. اگر حساب ساخته شود ولی اعمال فیلتر خطا بدهد، پنل این دو نتیجه را جدا اعلام می‌کند؛ خطای فیلتر را برطرف و دوباره اعمال کنید.

### فیلترهای هر کانفیگ

فیلترها با قوانین واقعی مسیریابی Xray برای شناسهٔ همان کاربر اعمال می‌شوند. پشتیبانی این کنترل‌ها برای کاربران **VLESS، VMess، Trojan و Shadowsocks در Xray** است. برای فیلتر دامنه، Sniffing مربوط به HTTP/TLS باید روشن و `metadataOnly` خاموش باشد. دیتای geosite هم باید در دسترس هسته باشد.

می‌توانید دسته‌های آماده و حداکثر ۱۰۰ دامنهٔ دلخواه، همراه زیردامنه‌ها، را مسدود کنید. اگر یک ایمیل/شناسه در چند اینباند استفاده شده باشد، قانون همان شناسه را در همهٔ آن‌ها هدف می‌گیرد.

این فیلترها دامنه/پروتکل قابل‌تشخیص را مسدود می‌کنند؛ بررسی تک‌تک تصاویر، ویدئوها یا همهٔ محتوای رمزگذاری‌شده نیستند. DNS مستقل برنامه‌ها، ECH و ترافیک مبهم می‌توانند تشخیص را محدود کنند.

### Gaming Mode چه می‌کند؟

برای کاربر انتخاب‌شده، UDP فاقد قانون قبلی را از خروجی مستقیم سرور عبور می‌دهد. قوانین فعلی اولویت دارند، TCP تغییر مسیر نمی‌دهد و UDP مقصد پورت 53 مستثناست. این حالت فشار مصنوعی، بافر بزرگ یا سرویس مانیتورینگ دائمی اضافه نمی‌کند.

اگر خروجی معمول از یک پراکسی اضافه عبور کند، ممکن است مسیر کوتاه‌تر شود؛ اگر از قبل مستقیم باشد، لزوماً تفاوتی ایجاد نمی‌شود. **کاهش پینگ تضمینی نیست** و IP خروجی UDP ممکن است تغییر کند. کلاینت و اینباند باید UDP را پشتیبانی کنند.

<a id="subscription"></a>
## صفحهٔ ساب و نمودار مصرف

وقتی لینک ساب درگاه پنل را در مرورگر باز می‌کنید، صفحهٔ اختصاصی اشتراک نشان داده می‌شود:

- نمودار حلقه‌ای حجم مصرف‌شده و نمایش سهم آپلود/دانلود؛
- حجم کل، باقی‌مانده و تاریخ انقضا یا حالت نامحدود؛
- کپی لینک و دریافت خروجی‌های V2Ray/Base64، Xray JSON و Clash/Mihomo؛
- دانلود فایل کانفیگ پروتکل‌های فایل‌محور، در صورت ارائهٔ آن‌ها توسط هستهٔ بومی؛
- نمایش جداگانهٔ منابع در اشتراک چندنودی.

آمار از `Subscription-Userinfo` بومی گرفته می‌شود. نمودارها **مصرف تجمیعی فعلی** هستند، نه تاریخچهٔ روزانهٔ ذخیره‌شده. مقادیر نامشخص با عدد ساختگی پر نمی‌شوند و سهمیهٔ نودهای مختلف با هم جمع نمی‌شود.

برنامه‌های کلاینت همچنان خروجی ساب اصلی را دریافت می‌کنند. پارامتر `?raw=1` خروجی خام را حتی برای مرورگر درخواست می‌کند. وجود هر فرمت به پروتکل و فعال‌بودن آن فرمت در تنظیمات بومی بستگی دارد.

لینک ساب خصوصی است. در صورت تنظیم آدرس ساب خارجی یا پل اختصاصی، آن آدرس حفظ می‌شود و نمایش صفحهٔ جدید در آن سرویس خارجی خودکار نیست.

<a id="logs"></a>
## لاگ جداگانهٔ کاربران

با حساب مدیر ارشد، کنار هر کلاینت یا در ویرایشگر آن، دکمهٔ **«لاگ» / «لاگ اتصال»** را باز کنید. برای آغاز ثبت، **«فعال‌سازی ثبت لاگ این سرور»** را بزنید.

نمایشگر زمان سرور، مبدأ، مقصد، مسیر و نوع رویداد را برای شناسهٔ دقیق همان کاربر نشان می‌دهد. در صفحهٔ نود، درخواست به همان نود فرستاده می‌شود.

- فعال‌سازی ثبت لاگ در سطح Xray آن سرور است؛ نمایش نتایج برای هر کاربر جدا فیلتر می‌شود.
- محتوای پیام‌ها ذخیره نمی‌شود، اما مقصد اتصال می‌تواند در لاگ دیده شود.
- تاریخچهٔ پیش از فعال‌سازی قابل بازسازی نیست.
- پروتکل یا هسته‌ای که شناسهٔ کاربر را در لاگ Xray ننویسد، در این نمایشگر قابل انتساب نیست.
- حداکثر ۲۰۰ رویداد از بخش پایانی فایل‌های اخیر خوانده می‌شود؛ تازه‌سازی دستی است.
- فایل‌های مدیریت‌شده هر پنج دقیقه از نظر اندازه بررسی می‌شوند و در آستانهٔ ۴ MiB چرخش دارند. این آستانه سقف سخت فضای دیسک نیست.
- تغییر وضعیت ثبت لاگ هسته را بازراه‌اندازی می‌کند. خاموش‌کردن آن ممکن است قابلیت محدودیت IP وابسته به لاگ را هم تحت تأثیر قرار دهد.

این بخش برای عیب‌یابی اخیر است؛ آرشیو کامل و تضمینی همهٔ اتصال‌ها نیست. مقصد لاگ سفارشی شما خودکار جایگزین نمی‌شود.

<a id="dns"></a>
## DNS و رابط AdGuard Home

رابط بومی AdGuard Home حفظ شده است. از بخش DNS می‌توانید کلاینت‌های مدیریت‌شده را بسازید و از بخش پیشرفته به تنظیمات کامل ادگارد، آمار، Query Log، فیلترها، Allowlist، بازنویسی DNS و تنظیمات رمزگذاری دسترسی داشته باشید.

### ساخت کلاینت اختصاصی DoH

1. در بخش کلاینت‌های DNS، افزودن کلاینت را بزنید.
2. نام، روز اعتبار، سهمیهٔ پیام‌های DNS و در صورت نیاز سقف تعداد پرس‌وجو را تنظیم کنید.
3. فعال‌شدن از اولین پاسخ موفق، IP مجاز یا اتصال به اولین IP را در صورت نیاز انتخاب کنید.
4. فیلترها و DNS بالادستی دلخواه را تنظیم کنید.
5. لینک اختصاصی، QR یا کد تنظیمات را دریافت کنید.

الگوی لینک:

```text
https://HOST:PANEL_PORT/dns-query/SECRET
```

DoH مدیریت‌شده به HTTPS نیاز دارد. لینک را در برنامهٔ پشتیبان DoH وارد کنید؛ کادر **Private DNS** اندروید معمولاً نام میزبان DoT می‌خواهد و این URL را قبول نمی‌کند. خروجی JSON این بخش، اطلاعات اتصال DNS است و ساب VPN محسوب نمی‌شود.

### معنای سهمیه و محدودیت‌ها

| گزینه | رفتار واقعی |
| --- | --- |
| سهمیهٔ حجم DNS | حجم پیام درخواست/پاسخ DNS؛ نه حجم دانلود سایت‌ها یا کل اینترنت دستگاه |
| اعتبار و محدودیت‌ها | برای لینک مدیریت‌شدهٔ `/dns-query/SECRET` اعمال می‌شوند |
| DNS عادی، DoT و DoQ بومی | مستقل‌اند و زیر پوشش سهمیهٔ این لینک نیستند |
| قفل IP | محدودیت آدرس شبکه؛ شناسایی قطعی دستگاه فیزیکی نیست |
| اولین IP | تغییر شبکه ممکن است به آزادکردن اتصال IP نیاز داشته باشد |
| فیلتر تبلیغات | نیازمند حفاظت فعال و فهرست بومی فعال و دانلودشده است |
| DNS تحریم‌شکن | به سرویس بالادستی و پشتیبانی آن از سایت هدف وابسته است؛ DNS به‌تنهایی IP وب را تغییر نمی‌دهد |

کاربران پشت NAT ممکن است IP مشترک داشته باشند. لینک محرمانه هم می‌تواند به اشتراک گذاشته شود؛ بنابراین قفل IP معادل تضمین «فقط یک دستگاه» نیست.

<a id="nodes"></a>
## افزودن نود و ساخت ساب ترکیبی

1. همین نسخهٔ پنل را روی سرور اصلی و نود نصب کنید و دسترسی HTTPS نود را بررسی کنید.
2. در پنل نود، بخش نودها و **«مشخصات اتصال این سرور»** را باز کنید.
3. گواهی اتصال و API Token را کپی کنید.
4. در پنل اصلی، آن‌ها را در **«افزودن یا اتصال مجدد نود»** وارد کنید و **«بررسی و افزودن نود»** را بزنید.
5. اینباندها و کلاینت‌های نود را از سرور انتخاب‌شده مدیریت کنید.
6. برای ساب ترکیبی، منابع و اشتراک‌های موردنظر را در بخش نودها انتخاب کنید.

توکن دسترسی نود محرمانه است. اتصال دارای گواهی معتبر عمومی، با تمدید معمول همان دامنه سازگار است. برای اتصال خودامضا، پس از تعویض گواهی لازم است مشخصات اتصال دوباره ثبت شود.

اگر یکی از منابع ساب ترکیبی در دسترس نباشد، دریافت کانفیگ ترکیبی خطا می‌دهد تا موقع به‌روزرسانی، کانفیگ‌های آن نود بی‌صدا از برنامهٔ کاربر حذف نشوند. صفحهٔ مرورگری وضعیت منبع ناموجود را مشخص می‌کند.

برای دریافت همهٔ قابلیت‌های جدید روی پنل اصلی **و هر نود** از `--repair` استفاده کنید. `--enable-nodes` فقط مسیر ارتقای محدود بخش نود است. کلاینت‌های DNS هر نود در پنل همان نود مدیریت می‌شوند.

<a id="network"></a>
## پورت‌ها و سازگاری با تونل

| پورت پیش‌فرض | کاربرد | وضعیت |
| --- | --- | --- |
| TCP 8443 | HTTPS پنل، ساب و DoH مدیریت‌شده | دسترسی ورودی لازم برای استفاده از این خدمات |
| TCP 8080 | پنل در حالت HTTP | فقط در صورت انتخاب این حالت |
| TCP 80 | تأیید صدور و تمدید گواهی HTTP-01 | برای SSL خودکار باید از اینترنت قابل دسترسی باشد |
| TCP/UDP 53 | DNS بومی | فقط با سیاست دسترسی متناسب با کاربران موردنظر |
| TCP 18080 | رابط داخلی vpn-ui | loopback؛ عمومی نکنید |
| TCP 18081 | رابط داخلی AdGuard | loopback؛ عمومی نکنید |
| TCP 2097 | ساب داخلی نصب تازه | loopback؛ عمومی نکنید |
| پورت اینباندها | ترافیک VPN | مطابق پروتکل و اینباندی که فعال می‌کنید |

نصاب تونل یا قوانین عمومی فایروال را خودکار نمی‌سازد. تونل باید TCP/UDP، پورت، MTU و TLS لازم برای پروتکل انتخابی را پشتیبانی کند؛ سازگاری با تمام تونل‌ها تضمین نشده است.

برای عبور پنل از پراکسی معکوس، مسیر خصوصی پنل، مسیرهای `/_alireza/`، `/dns-query/` و WebSocket موردنیاز را به درگاه درست برسانید. تونل TCP ممکن است IP واقعی کاربر را پنهان کند و معنای قفل IP در DNS را تغییر دهد. تنظیم `dns_trusted_proxies` فقط برای CIDR دقیق پراکسی مورداعتماد است؛ همهٔ اینترنت را پراکسی قابل‌اعتماد تعریف نکنید.

<a id="upgrade"></a>
## به‌روزرسانی و بکاپ

ابتدا بکاپ بگیرید:

```bash
sudo alirezapanel backup
```

بعد نسخهٔ فعلی مخزن را دریافت و تعمیر/به‌روزرسانی کنید:

```bash
curl -fL --retry 3 --connect-timeout 15 --max-time 180 https://raw.githubusercontent.com/alirezachatgpt97-coder/alirezapanel/main/install.sh -o install.sh && sudo bash install.sh --repair
```

با root می‌توانید `sudo` را حذف کنید. این کار را روی پنل اصلی و همهٔ نودها انجام دهید. سپس اجرا کنید:

```bash
sudo alirezapanel check
sudo alirezapanel ssl status
```

`--repair` تنظیمات و کاربران را حفظ و قبل از تغییرات مدیریت‌شده بکاپ ایجاد می‌کند، اما هنگام اجرا سرویس‌ها موقتاً متوقف می‌شوند. این دستور باینری‌های **نسخه‌های مشخص‌شده در نصاب** را نصب می‌کند؛ به‌روزرسانی آزاد به آخرین نسخهٔ تمام اجزا نیست.

بکاپ‌های محلی در `/var/backups/alirezapanel/` قرار می‌گیرند و شامل داده‌ها و اطلاعات حساس‌اند. برای بازیابی پس از خرابی کامل دیسک، یک نسخهٔ محفوظ خارج از همان سرور نگه دارید. فرمان عمومی `restore` در CLI فعلی وجود ندارد؛ بازیابی باید با نسخه و ساختار بکاپ هماهنگ انجام شود.

<a id="resources"></a>
## مصرف منابع

صفحهٔ ساب از SVG و CSS داخلی استفاده می‌کند و نمودارخانه، فونت بیرونی یا تازه‌سازی مداوم ندارد. نمایشگر لاگ فقط هنگام بازکردن یا تازه‌سازی دستی داده می‌خواند. ثبت لاگ اختیاری و فایل‌های آن دارای چرخش دوره‌ای‌اند. DoH مدیریت‌شده محدودیت هم‌زمانی دارد و هسته‌های VPN اختیاری تا زمان نیاز فعال نمی‌شوند.

حدهای حافظهٔ Go هدف نرمِ جمع‌آوری حافظه‌اند، نه سقف قطعی کل مصرف سرور. روی VPS کوچک فقط هسته‌های لازم را فعال کنید و اندازهٔ فهرست‌های فیلتر و مصرف واقعی را بررسی کنید. رابط‌های بومی ممکن است پایش دوره‌ای خودشان را داشته باشند؛ ادعای «بدون هیچ پردازش پس‌زمینه» برای کل پنل صحیح نیست.

<a id="troubleshooting"></a>
## رفع مشکلات رایج

### پنل باز نمی‌شود یا صفحهٔ اصلی IP خطای 404 می‌دهد

آدرس کامل را بگیرید؛ ریشهٔ دامنه جایگزین مسیر خصوصی پنل نیست:

```bash
sudo alirezapanel info
sudo alirezapanel check
sudo alirezapanel status
sudo alirezapanel logs
```

پورت عمومی انتخاب‌شده، فایروال سیستم و فایروال شرکت میزبان را بررسی کنید.

### خطای پورت اشغال‌شده

```bash
sudo ss -lntup
```

سرویس استفاده‌کننده از پورت را شناسایی کنید. نصاب قرار نیست DNS یا وب‌سرور نامرتبط را بدون هماهنگی متوقف کند. پورت 80 برای ACME و پورت 53 برای DNS را هم بررسی کنید.

### صدور یا تمدید SSL خطا می‌دهد

```bash
sudo alirezapanel ssl status
sudo alirezapanel ssl renew
sudo journalctl -u alirezapanel-cert-renew.service -n 100 --no-pager
```

دامنه/IP، رکوردهای A/AAAA، مسیر NAT و دسترسی TCP 80 را بررسی کنید. برای نصب با `ip-acme` بدون منوی تعاملی، `ALIREZA_HOST` باید مشخص باشد. گواهی خودامضا، SSL معتبر عمومی محسوب نمی‌شود.

### نود وصل نمی‌شود

HTTPS نود، گواهی، API Token و دسترسی شبکهٔ سرور اصلی به نود را بررسی کنید. در پنل، «بررسی اتصال» را بزنید. در صورت تعویض گواهی خودامضا، اتصال را دوباره ثبت کنید. قابلیت‌های جدید نیازمند `--repair` روی همان نود هم هستند.

### فیلتر اعمال نمی‌شود

نوع هسته و پروتکل، Sniffing و دیتای geosite را بررسی کنید. موفقیت ساخت کلاینت به‌تنهایی به معنی موفقیت اعمال فیلتر نیست. متن خطای همان عملیات و لاگ VPN را بخوانید:

```bash
sudo journalctl -u alirezapanel-vpn.service -n 100 --no-pager
```

### ساب خالی یا یکی از فرمت‌ها ناموجود است

فعال‌بودن اشتراک در تنظیمات بومی، شناسهٔ اشتراک، وضعیت حساب/اینباند و پشتیبانی پروتکل از فرمت انتخابی را بررسی کنید. برای ساب چندنودی، همهٔ منابع باید هنگام دریافت کانفیگ در دسترس باشند. برای دریافت خام از مرورگر از `?raw=1` استفاده کنید.

### لاگ کاربر خالی است

ثبت لاگ را فعال کنید، با همان کاربر ترافیک جدید ایجاد و نمایشگر را دستی تازه کنید. شناسه باید دقیقاً یکسان باشد. نبود نتیجه در فایل‌های اخیر، اثبات نبود تمام اتصال‌های قبلی نیست. هسته‌های فاقد شناسهٔ ایمیل در لاگ Xray در این نمایشگر پوشش داده نمی‌شوند.

### DoH یا فیلتر DNS کار نمی‌کند

SSL، URL اختصاصی، اعتبار و سهمیه، قفل IP و دسترسی DNS بالادستی را بررسی کنید. برنامه باید DoH را پشتیبانی کند. برای فیلتر تبلیغات، حفاظت و فهرست فعال ادگارد لازم است:

```bash
sudo journalctl -u alirezapanel-dns.service -n 100 --no-pager
```

<a id="validation"></a>
## وضعیت بررسی و گزارش خطا

بررسی‌های توسعه شامل نحو نصاب، کدهای Python داخلی، API نود و DNS، حفظ خروجی ساب، محدودسازی خواندن لاگ و آزمون‌های DOM رابط بوده است. پنل و هستهٔ مشخص‌شده با ترافیک واقعی محلی VLESS/TLS و UDP برای کنترل فیلتر، Gaming و انتساب لاگ بررسی شده‌اند.

این موارد معادل تأیید همهٔ پروتکل‌ها، همهٔ تونل‌ها، صدور عمومی ACME یا آزمون فشار روی VPS واقعی یک‌گیگ نیستند. پس از نصب، `alirezapanel check` و اتصال واقعی کلاینت‌ها را روی سرور خودتان بررسی کنید.

برای [گزارش مشکل](https://github.com/alirezachatgpt97-coder/alirezapanel/issues)، این اطلاعات را بفرستید:

- نسخهٔ پنل و سیستم‌عامل؛
- معماری، CPU و RAM؛
- فرمان اجراشده و مراحل بازتولید مشکل؛
- خروجی مرتبط `check` و لاگ سرویس.

پیش از انتشار، رمز، توکن نود، لینک ساب/DoH خصوصی و کلیدها را از خروجی حذف کنید.
