# ALIREZAPANEL 2.8.0

پنل مدیریت VPN، کاربران، اینباندها، ادمین‌ها، نودها و Subscription، همراه با دسترسی به رابط **بومی AdGuard Home**.

این نسخه بر پایهٔ آخرین کد مخزن `alirezachatgpt97-coder/alirezapanel` در زمان شروع کار، commit زیر ساخته شده است:

`b51f7480623cf050debdbb3f39eacd71fbe399cf`

این پروژه **alirezaserver نیست**. کد اجرایی یکپارچه‌سازی داخل `install.sh` قرار دارد. فایل‌های آزمون و راهنما به‌صورت جداگانه همراه بسته هستند. نصب‌کننده، نسخه‌های مشخص و کنترل‌شدهٔ هسته‌ها را از اینترنت دانلود می‌کند؛ ZIP یک بستهٔ نصب **آنلاین** است و باینری‌های حجیم بالادستی را داخل خود ندارد.

## تغییرات این نسخه

- اصلاح بازنویسی آدرس API نود: پیشوند نود فقط به منابع و مسیرهای رابط افزوده می‌شود، نه به درخواست‌هایی که Axios خودش پیشوندگذاری می‌کند. نود با مسیر `/` و مسیر اختصاصی پشتیبانی می‌شود.
- اصلاح مسیرهای رابط Core و انتخاب سرور؛ فرم‌ها و پروتکل‌های بومی حفظ شده‌اند.
- خطای احراز هویت نود پیام قابل اقدام دارد و درخواست تغییردهنده دوباره اجرا نمی‌شود.
- حساب ادمین بدون مجوز صفحه، به‌جای متن خام، صفحهٔ روشن عدم دسترسی با دکمهٔ خروج می‌گیرد. هیچ مجوزی خودکار افزایش نمی‌یابد. ادمین دارای مجوز به بخش مجاز خودش هدایت می‌شود.
- طراحی Aurora برای ورود، داشبورد، جدول‌ها، فرم‌ها، پنجره‌ها، نودها و ادمین‌ها؛ رنگ‌های هماهنگ، حالت روشن/تیره، فارسی/انگلیسی و جهت RTL/LTR.
- بخش مستقل **فیلتر محتوا / Content filters** در منو: انتخاب سرور، جست‌وجوی کاربران و خواندن/اعمال تنظیمات واقعی فیلتر و Gaming Mode.
- حذف رابط مستقل «کلاینت DNS» از پنل. رابط، تنظیمات و داده‌های AdGuard تغییر داده نمی‌شوند. لینک‌های مدیریت‌شدهٔ DNS نسخه‌های قبلی و داده‌هایشان برای سازگاری حفظ می‌شوند.
- حذف نوار فیلتر/SSL از بالای صفحات؛ مدیریت HTTPS، گواهی‌ها و تمدید از تنظیمات بومی و فرمان `alirezapanel ssl` همچنان در دسترس است.
- یک حلقهٔ جایگزین وضعیت داشبورد با فاصلهٔ ۵ ثانیه، توقف در صفحهٔ پنهان و جلوگیری از درخواست هم‌پوشان. WebSocket بومی حفظ شده است.
- کش دارایی‌های نسخه‌دار، کاهش کار تکراری روی DOM و حذف ساخت پایگاه داده/جلسهٔ DNS اضافی در نصب تازه.
- پشتیبان ارتقا شامل اطلاعات پنل، داده‌های VPN/AdGuard/نود، کد Gateway، فایل‌های سرویس و CLI است.

## پیش‌نیاز و نصب تازه

Debian 12/13 یا Ubuntu 24.04، معماری x86_64/amd64، دسترسی root و systemd واقعی لازم است. هدف نصب پایه، **یک هسته و یک گیگابایت RAM** است. اجرای همهٔ سرویس‌ها زیر هر مقدار بار روی یک گیگابایت تضمین نشده است. Docker، Node.js، npm و ابزار کامپایل روی سرور مقصد نصب نمی‌شوند.

حداقل ۲ گیگابایت فضای آزاد برای نصب در نظر بگیرید؛ ارتقا علاوه بر فضای نصب، به فضای نسخهٔ پشتیبان داده‌های موجود نیاز دارد. پروتکل‌های Kernel به قابلیت‌های واقعی VPS وابسته‌اند.

پس از قرار دادن فایل‌های این نسخه در شاخهٔ `main` همین مخزن، نصب یک‌خطی:

```bash
curl -fL --retry 3 --connect-timeout 15 --max-time 180 https://raw.githubusercontent.com/alirezachatgpt97-coder/alirezapanel/main/install.sh -o install.sh && sudo bash install.sh
```

**تا قبل از جایگزینی فایل‌های GitHub، این دستور نسخهٔ فعلی GitHub را دریافت می‌کند، نه بستهٔ تحویلی 2.8.0.** برای بررسی همین بسته، ZIP را باز کنید و از فایل محلی استفاده کنید:

```bash
bash install.sh --self-test
sudo bash install.sh
```

نصب روی سرور تازه انجام می‌شود؛ انتقال خودکار از پنل‌های دیگر پشتیبانی نمی‌شود. روی نصب موجود همین پروژه، اجرای بدون `--repair` تنظیمات را حفظ می‌کند و نصب دوباره انجام نمی‌دهد.

حالت اتصال را در Wizard انتخاب کنید: دامنه با گواهی معتبر، IP با گواهی ACME، گواهی خودامضا یا HTTP. نودها برای اتصال به یکدیگر HTTPS لازم دارند. پورت عمومی پیش‌فرض HTTPS برابر 8443 و HTTP برابر 8080 است؛ تنظیمات Wizard می‌تواند آن را تغییر دهد.

نصب غیرتعاملی نمونه:

```bash
sudo env ALIREZA_TLS_MODE=domain ALIREZA_HOST=panel.example.com bash install.sh
```

رمز اولیه به‌صورت تصادفی تولید می‌شود، مگر آنکه `ALIREZA_PASSWORD` با طول ۱۶ تا ۷۲ بایت UTF-8 داده شود. اطلاعات ورود:

```bash
sudo alirezapanel credentials
```

## ارتقای نسخهٔ موجود

فایل محلی **همین بسته** را روی سرور اصلی و همهٔ نودها قرار دهید. ابتدا پشتیبان بگیرید، سپس:

```bash
sudo alirezapanel backup
sudo bash install.sh --repair
sudo alirezapanel check
```

`--repair` خودش نیز قبل از جایگزینی فایل‌ها پشتیبان جداگانه می‌سازد و سرویس‌ها را موقتاً متوقف می‌کند. نام کاربری، ادمین‌ها، کاربران، اینباندها، نودها، تنظیمات، گواهی‌ها و پایگاه داده‌های موجود حفظ می‌شوند. YAML مربوط به AdGuard در ارتقا بازنویسی نمی‌شود. تغییر نسخهٔ باینری بالادستی و مهاجرت از `alirezaserver` انجام نمی‌شود.

برای تغییرات کامل این نسخه از `--repair` استفاده کنید؛ `--enable-nodes` فقط به‌روزرسانی پل نود است. بعد از ارتقای همهٔ سرورها، مرورگر را تازه‌سازی کامل کنید و در بخش نودها «بررسی اتصال» بزنید. توکن‌های موجود به‌صورت خودکار لغو نمی‌شوند. گواهی عمومی معتبر، تمدید معمول خود را ادامه می‌دهد؛ گواهی خودامضا با تغییر fingerprint نیازمند اتصال مجدد است.

## اتصال و مدیریت نود

1. همین نسخه را روی سرور مقصد نصب یا با `--repair` ارتقا دهید و HTTPS را فعال کنید.
2. در مقصد وارد بخش «نودها» شوید و «مشخصات اتصال این سرور» را باز کنید.
3. بستهٔ گواهی عمومی و API Token را در بخش افزودن نودِ سرور اصلی وارد کنید.
4. «بررسی و افزودن» هویت و دسترسی واقعی کاتالوگ را کنترل می‌کند.
5. در صفحات اینباند، کلاینت یا Core، سرور مقصد را انتخاب کنید. هر تغییر فقط روی همان سرور اجرا می‌شود.

توکن یک اجازهٔ محدود برای عملیات پل نود است، نه نشست ورود پنل. آن را منتشر نکنید. اتصال نیازمند آدرس قابل دسترس، پورت درست و اعتبار گواهی است. در صورت لغو توکن، غیرفعال‌شدن Connector یا تغییر گواهی خودامضا، مشخصات مقصد را دوباره تهیه و اتصال را ثبت کنید.

Subscription ترکیبی، خروجی‌های واقعی هسته‌ها را جمع‌آوری می‌کند. اگر منبع قطع باشد، پاسخ ناقص جایگزین تنظیمات کاربر نمی‌شود. فایل‌های اختصاصی پروتکل‌ها از رابط بومی همان نود قابل دریافت‌اند.

## ادمین‌ها و ورود

لینک ورود همهٔ ادمین‌ها همان **URL عمومی و مسیر خصوصی پنل** است که `alirezapanel credentials` نشان می‌دهد؛ نیازی به لینک ورود ساختگیِ جدا برای هر حساب نیست. دکمهٔ صفحهٔ ورود در بخش ادمین‌ها همین مسیر را باز می‌کند. اگر در همان مرورگر نشست دیگری باز است، ابتدا خارج شوید یا از پنجرهٔ خصوصی استفاده کنید.

برای هر ادمین، مجوز یک صفحه مانند `accessInbounds` یا `accessOverview` و اینباندهای مجازش را مشخص کنید. مجوز یک اقدام مانند ساخت کلاینت، به‌تنهایی مجوز باز کردن یک صفحه نیست. حساب بدون مجوز صفحه می‌تواند وارد شود و خارج شود، ولی برای دیدن بخش‌ها باید مدیر اصلی به آن مجوز بدهد. رمز، 2FA، نشست و جداسازی دسترسی‌ها توسط کنترلر بومی بررسی می‌شوند.

## DNS، فیلتر محتوا و HTTPS

**DNS** فقط رابط بومی AdGuard Home را در یک قاب هم‌مبدأ و با کنترل دسترسی مدیر اصلی باز می‌کند. کلاینت‌های داخل خود AdGuard حذف نشده‌اند. سرویس DNS، لیست‌ها، Query Log، Upstreamها و تنظیمات آن دست‌نخورده‌اند. داده‌ها و لینک‌های DNS اضافیِ قدیمی حذف نمی‌شوند؛ رابط مدیریتی مستقل آن بخش دیگر نمایش داده نمی‌شود.

**فیلتر محتوا** مستقل است و به سیاست‌های موجود Xray متصل می‌شود. سرور و کاربر را انتخاب کنید، تنظیمات فعلی را بخوانید و تغییر دهید. دامنه‌های دلخواه، دسته‌بندی‌ها و Gaming Mode حفظ شده‌اند. VLESS، VMess، Trojan و Shadowsocks روی Xray پشتیبانی می‌شوند. تغییر تنظیمات هسته ممکن است اتصال‌ها را کوتاه قطع کند. Geosite معتبر، Sniffing لازم و پشتیبانی UDP در کلاینت برای گزینه‌های مربوط ضروری است. فیلتر دامنه تضمین پوشش تمام محتوای رمزگذاری‌شده نیست.

**HTTPS و گواهی‌ها** فعال می‌مانند. فرم TLS اینباند و تنظیمات بومی حذف نشده‌اند. مدیریت گواهی و تمدید:

```bash
sudo alirezapanel ssl
```

## امکانات و پروتکل‌ها

کنترل‌های بومی مدیریت کاربر، اینباند، سهمیه، انقضا، Core، آمار، لاگ، Backup، Subscription و Native Config باقی هستند. این نسخه موتور تولید پروتکل یا باینری هسته‌ها را تغییر نمی‌دهد.

VLESS، VMess، Trojan، Shadowsocks، Hysteria/Hysteria2، AnyTLS، TUIC، Naive، MTProto، SSH، WireGuard، AmneziaWG، OpenVPN، L2TP، PPTP، OpenConnect، SSTP، IKEv2 و GRE مطابق قابلیت‌های هسته و سیستم‌عامل قابل مدیریت‌اند. حفظ کد پروتکل به معنی آزمون زندهٔ همهٔ این پروتکل‌ها نیست.

## آزمون و حدود اطمینان

- آزمون‌های رگرسیون Python و کنترل‌های DOM/JavaScript اجرا شده‌اند.
- دو نمونهٔ واقعی vpn-ui v1.9.4 با SHA کنترل‌شده و Gatewayهای HTTPS در محیط محلی آزموده شدند: نود با مسیر `/` و مسیر اختصاصی، ساخت/ویرایش/حذف اینباند، کلاینت، جداسازی مقصد، احراز هویت و ادمین محدود.
- Bash و همهٔ ماژول‌های Python داخل نصب‌کننده بررسی شده‌اند.
- **مرورگر این محیط با SIGTRAP هنگام شروع متوقف شد؛ بررسی دیداری موبایل/دسکتاپ انجام نشده است.** آزمون Playwright برای اندازه‌های 1366×900 و 390×844 و فارسی/انگلیسی در بسته موجود است.
- نصب واقعی systemd، ACME روی اینترنت، پروتکل‌های Kernel، اجرای کامل AdGuard و اندازه‌گیری RAM/CPU روی VPS یک‌گیگابایتی در این محیط انجام نشده‌اند.

[گزارش دقیق آزمون‌ها](docs/VALIDATION.md) · [منابع و هدف یک گیگابایت](docs/RESOURCES.md)

آزمون‌های توسعه، خارج از سرور واقعی:

```bash
bash install.sh --self-test
python3 tests/test_regressions.py
python3 tests/extract.py /path/to/private/test-runtime
node tests/ui_harness.js /path/to/private/test-runtime
python3 tests/native_integration.py /path/to/vpn-ui-amd64 /path/to/test-output
```

آزمون بومی به Python دارای `aiohttp` و `PyYAML`، OpenSSL و باینری pinned نیاز دارد. Node.js فقط برای آزمون توسعه است. فایل‌های تست حاوی رمز ساختگی برای محیط موقت هستند؛ از آن روی سرور واقعی استفاده نکنید.

## فایل‌های قابل قرار دادن در GitHub

محتویات ZIP را در **ریشهٔ همین مخزن** قرار دهید:

| فایل یا پوشه | کاربرد |
|---|---|
| `install.sh` | نصب‌کننده و تمام کد اجرایی یکپارچه‌سازی |
| `README.md` | نصب و استفادهٔ نسخهٔ جدید |
| `CHANGELOG.md` | تغییرات و علت اصلاح‌ها |
| `LICENSE` | مجوز GPL-3.0 |
| `SOURCES.md` | منابع و نسخه‌های pinned |
| `SHA256SUMS` | بررسی سلامت فایل‌های بسته |
| `docs/` | راهنمای ارتقا، بازگشت، منابع و آزمون‌ها |
| `tests/` | آزمون‌های قابل تکرار |

ساختار پوشه‌ها را حفظ کنید. فایل ZIP، لاگ‌های محلی، پایگاه دادهٔ تست، رمز، گواهی خصوصی یا باینری‌های دانلودشده را به ریشهٔ مخزن اضافه نکنید. برای نصب اجرایی، `install.sh` کافی است؛ سایر فایل‌ها برای بررسی و نگهداری همراه‌اند.
